# Weekend-Now（MVP demo）

Weekend-Now 是一个 AI 驱动的周末本地生活推荐 Demo，用于验证「轻量问答 + AI 推荐解释」的产品体验。

当前版本并未接入真实高德地图 / Google Places API，而是使用固定 POI 候选池模拟地点数据。推荐接口会根据用户的滑卡偏好、三题情境问答和候选 POI 信息，让模型从候选池中选择 3 个最匹配的地点，并生成推荐理由。

因此，本项目重点验证的是：
- 用户是否愿意通过轻量问题表达周末偏好
- AI 是否能基于候选池生成合理推荐
- 推荐理由是否能提升用户理解和决策效率
- MVP 交互链路是否完整

## 项目背景

对于许多城市年轻人而言周末最大的难题并不是没有选择，而是选择太多。用户往往会经历：
•打开地图 App
•搜索附近地点
•浏览大量评价
•在多个候选之间反复犹豫最终产生决策疲劳。
与此同时，用户真实需求往往并非：我想找一家咖啡馆。而是：我今天有点累，想出去走走。

这是一个典型的模糊需求场景。因此，我们尝试探索：AI 是否能够理解用户当前状态，并帮助用户完成决策。

## 用户痛点

- 痛点1：选择过多。用户知道附近有很多地方。但不知道：今天更适合去哪一个。
- 痛点2：需求模糊。用户往往无法准确表达：想吃什么，想玩什么。但能够表达：想放松，想约会，想换个环境
- 痛点3：决策成本高。传统地图产品提供大量信息。但用户仍需要自行比较和筛选。

## 产品目标

验证以下核心假设：

• 用户愿意通过轻量问答表达当前状态。
• AI 推荐理由能够提升用户信任感。
• 相比纯列表展示，

带解释的推荐结果更容易帮助用户做出决策。

## 产品方案

• Step1：冷启动建档
用户通过滑卡完成偏好采集：环境偏好、消费偏好、活动偏好、社交偏好
形成基础口味画像。

• Step2：今日情境输入
用户回答三道问题：几个人、当前状态、愿意接受的距离
用于表达即时需求。

• Step3：AI 推荐
系统综合：长期口味偏好、当前情境、候选 POI 信息
生成推荐结果。

• Step4：推荐解释
除推荐地点外，系统同时生成推荐理由。
例如：结合你今天想放松的状态，这里相比商场更加安静，也更适合一个人散步。

• Step5：出行反馈
用户决定去处后进入反馈流程。反馈结果用于更新口味画像。

## AI能力设计

AI 在哪里发挥作用--AI 不负责寻找地点。AI 负责：

1. 理解用户情境

例如：一个人,想放松,不想跑太远

2. 从候选集合中筛选地点

当前版本使用固定 POI 候选池。AI 需要从候选池中选择最匹配的地点。

3. 生成推荐理由

解释：为什么推荐这里。提升推荐的可解释性和信任感。

## 评测方案

当前版本已完成一轮轻量情境评测，并基于 Bad Case 对 Prompt 进行了第二轮优化验证。

由于 Weekend-Now 当前仍是固定 POI 池 Demo，评测目标不是验证真实地图召回能力，也不是验证线上转化效果，而是验证：

- 模型是否能在候选 POI 池内选择合适地点
- 推荐是否符合用户的三题情境输入
- 推荐理由是否能够解释“为什么推荐这里”
- Prompt 优化是否能减少典型 Bad Case

### 评测数据

已构建 40 条典型周末出行情境评测集，覆盖以下组合：

- 出行人数：1 人、2 人、3 人以上
- 当前状态：想放松、想新鲜感、想热闹、想运动、随便逛逛、临时起意
- 距离偏好：步行 15 分钟、地铁 30 分钟、不限距离

每条 Case 会输入相同的固定 POI 候选池，由模型返回 3 个推荐地点及推荐理由。

### 评分方式

采用人工 Rubric 评分，每项 1～5 分，总分 20 分。

| 评测维度 | 满分 | 判断标准 |
|---|---:|---|
| 情境匹配度 | 5 | 推荐是否符合用户人数、状态和出行动机 |
| 地理合理性 | 5 | 推荐是否符合用户距离偏好 |
| 推荐理由质量 | 5 | 理由是否结合用户情境和 POI 特征，而不是泛泛而谈 |
| 推荐多样性 | 5 | 3 个推荐是否提供不同类型的体验，避免高度同质化 |

人工评分不是凭感觉直接打分，而是先定义统一评分标准，再逐条评估推荐结果，用于提升评测结果的一致性和可解释性。

### 第一轮评测：Prompt V1

第一轮使用初版 Prompt 跑完 40 条评测集。整体结果较稳定，大部分 Case 能够遵守候选池约束，并返回符合场景的推荐。

第一轮评测发现的主要问题：

1. “想放松”场景下，模型偶尔会推荐偏运动属性的 POI，例如骑行驿站；
2. “想新鲜感”场景下，模型有时会退化为推荐常规咖啡馆，探索感不足；
3. 部分需求如温泉、郊游、露营、桌游、茶馆，在当前固定 POI 池中覆盖不足。

### Prompt V2 优化方向

基于第一轮 Bad Case，对 Prompt 做了定向优化：

- 当用户选择“想放松”时，优先推荐安静、慢节奏、低刺激、适合独处或轻松交流的地点，降低运动类或强刺激活动的优先级；
- 当用户选择“想新鲜感”时，优先推荐展览、创意空间、快闪市集、特色小店等具有探索感的地点，避免仅因为环境不同就推荐常规咖啡馆；
- 强化推荐理由要求：理由需要结合用户当前情境和 POI 特征，避免模板化表达。

### 第二轮评测：Prompt V2

第二轮使用同一批 40 条情境评测集重新跑分。对比 Prompt V1，Prompt V2 在“放松”和“新鲜感”相关 Case 上有明显改善：

- “放松”场景中，运动类 POI 的误推荐减少；
- “新鲜感”场景中，推荐结果更偏向探索、展览、创意空间和特色体验；
- 仍未改善的 Case 主要集中在 POI 池覆盖不足，例如温泉、露营、桌游、茶馆等当前候选池中不存在或数量不足的类型。

因此，本轮评测结论是：

> 当前 Prompt 已能较稳定地完成情境理解和推荐理由生成；Prompt V2 对部分语义理解问题有改善，但固定 POI 池的覆盖范围仍是推荐质量的主要上限。

## Bad Case

基于两轮评测结果，当前 Bad Case 主要分为两类：Prompt 问题和 POI 池问题。

### 1. Prompt 问题

#### Bad Case 1：“想放松”被误理解为轻运动

部分 Case 中，用户选择“想放松”，但模型推荐了带有运动属性的地点，例如骑行驿站。

问题分析：

- 用户的“放松”更接近安静、慢节奏、低刺激；
- 模型可能将“出门走走”理解成“户外活动”或“轻运动”；
- 这会导致推荐和用户真实状态存在偏差。

优化方式：

- 在 Prompt V2 中明确约束“想放松”优先对应安静、慢节奏、低社交压力；
- 降低骑行、强运动、强刺激活动的优先级。

#### Bad Case 2：“想新鲜感”退化为普通咖啡馆推荐

部分 Case 中，用户选择“想新鲜感”，但模型推荐了常规咖啡馆。

问题分析：

- “新鲜感”不等于“换个地方坐”；
- 用户更可能期待展览、快闪、创意园、特色小店等探索型体验；
- 常规咖啡馆虽然安全，但探索感不足。

优化方式：

- 在 Prompt V2 中明确“新鲜感”优先对应探索、新体验、创意空间、展览和特色店；
- 避免仅因为地点环境不同就推荐普通咖啡馆。

### 2. POI 池问题

#### Bad Case 3：温泉 / 郊游需求无法满足

部分 Case 的期望方向是温泉、郊游、近郊放松，但当前固定 POI 池主要是城市内咖啡馆、展览、餐吧、社区空间等地点。

问题分析：

- 当前候选池中缺少温泉、近郊目的地、自然型出游地点；
- 即使 Prompt 优化，模型也只能从候选池里选择相对接近的地点；
- 这类问题本质上不是模型理解问题，而是候选池覆盖不足。

#### Bad Case 4：桌游 / 茶馆类需求覆盖不足

部分多人聚会场景期望桌游、茶馆等低强度社交场所，但当前 POI 池中缺少对应类型。

问题分析：

- 模型会退而求其次推荐餐吧、夜市、露营餐吧等社交属性较强的地点；
- 推荐方向不算完全错误，但不够贴近期望；
- 后续如果接入真实 POI 数据，需要补充更多细分业态。

### Bad Case 归因结论

当前 Bad Case 不是全部由 Prompt 导致。根据两轮评测结果，大致可以归为：

- Prompt 可优化问题：放松场景语义不够精准、新鲜感场景探索感不足；
- POI 池问题：温泉、郊游、露营、桌游、茶馆等候选类型不足。

因此，后续优化方向分为两条：

1. 继续细化 Prompt，提高对用户状态的语义理解；
2. 扩充或接入真实 POI 数据，提高候选池覆盖度。
